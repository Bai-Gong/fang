# 百工·坊（Fang）目标与里程碑

> 本文回答「做到什么、分几步、每步怎么算数」。为什么做见
> [产品分析.md](产品分析.md)，首版骨架的技术取舍见
> [工程骨架决策.md](工程骨架决策.md)。状态快照：2026-10-22。

## 开发目标

为六个创作工具（墨、剪、陶、乐、筑、锻）提供统一的桌面外壳与 UI
基础设施：停靠面板系统、快捷键/命令框架、主题 token、菜单栏、通用
控件。以 npm 私有包 `@baigong/fang` 按 semver 分发；**不做任何业务
功能**（时间线、图层、波形等归各工具）；纸不接入坊（界面范式独立，
产品分析已有结论）。API 全部从真实工具的消费需求沉淀，不超前抽象。

## 状态快照

v0.1.0 骨架已落地并通过验证（token、keybinding + useHotkeys、
DockHost/DockPanel 三模块，vitest 42/42，smoke 五步全绿）。当前唯一
真实消费方是剪，走 vite/tsconfig alias 直连 `../fang/src` 联调轨；
私有 registry 未搭建。

## 里程碑（每条以消费方真实需求为准入）

- **M1（已完成）首版骨架**：单包 0.1.0，三个「不猜也知道对」的
  模块。准入：剪 M0 的四区布局建在其上。
- **M2 分发轨定案**：alias 联调轨 → 私有 registry（或 git 依赖）的
  决策与迁移、CHANGELOG 纪律、main 发布流水线。准入：剪与锻都能
  锁定引用一个确定版本，联调不再依赖目录相对路径。
- **M3 剪 M2 反哺批**：时间线所需通用控件（滑杆、数字输入、颜色
  选择）、useHotkeys 按剪的实际快捷键表打磨、Dock 面板拖拽最小集。
  准入：剪 M2（画布操纵/修剪三式/撤销重做）直接复用而非私造控件。
- **M4 剪 M3-M4 反哺批**：命令面板、菜单栏、Dock 工作区布局的
  保存/恢复。准入：剪的效果库与多序列 UI 建于其上。
- **M5 第二工具铺开**：墨或陶接入时的批量反哺（工具栏框架、属性
  面板、画布容器）。准入：第二个创作工具以坊为壳跑起来。
- **M6+（推迟项池）**：Dock 浮动/多工作区、i18n、无障碍、更新
  通道——等真实消费方提出再动。

## 原则

- 每个里程碑以某个工具的真实消费需求为准入条件，不为了齐备而齐备。
- 剪是第一消费方：剪的每个功能里程碑落地时，同步评估「该反哺什么
  进坊」，避免工具侧私造后回迁的浪费。
- 破坏性 API 变更走主版本；六工具并行消费时任何变更先过剪的联调。
