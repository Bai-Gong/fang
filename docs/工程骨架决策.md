# 百工·坊（Fang）工程骨架决策

> 首版工程骨架的方案定夺、四轮评审修订与实测留档 · 2026-10-19
> 关联：[README](../README.md)、[产品分析](产品分析.md)。本文为决策留档，不随日常开发更新；后续重大转向另起条目追加。

## 一、总览

- **单包不拆仓**：仓库根即包根（`@baigong/fang`），不引入 `packages/` 层或 monorepo 工具。根 AGENTS.md 规定集群根目录不放业务代码、各项目独立 git 仓库，pnpm workspace 需要根配置文件违反集群约定；包边界只有靠第一个真实消费者才能验证（六目录当时均无代码），现在拆包必是猜。
- **0.1.0 起步**，private、ESM-only（`type: module`）。semver 0.x 期间 minor 即允许破坏，破坏点记 CHANGELOG.md；私有 registry、CI、git hooks 推迟（无 git remote）。
- **首版只放三个「不猜也知道对」的模块**：设计 token（深色默认，产品分析既定事实）、keybinding 解析器 + useHotkeys（纯逻辑可全量单测）、DockHost / DockPanel 朴素停靠壳。
- **不放 Rust 代码、不建 src-tauri**（README 定位章节明定 Tauri 为可选层）。
- **明确不建**：`src-tauri/`、`packages/`、`.github/`、根目录任何 workspace 配置。

## 二、目录与交付物

| 路径 | 职责 |
| --- | --- |
| `package.json` | exports：`.` → `{ types: ./dist/types/index.d.ts, import: ./dist/es/index.js }`、`./tokens.css` → `./dist/tokens.css`；`sideEffects: ["**/*.css"]`；`files: ["dist"]`；engines `^20.19.0 \|\| >=22.12.0`；peer `react ^18 \|\| ^19` |
| `vite.lib.config.ts` | 库构建：ES 单格式；`rollupOptions.external: [/^react($|\/)/, /^react-dom($|\/)/]` 为**硬性要求**；`fileName` 显式钉死 `index.js` 与 exports 契约对齐 |
| `vite.config.ts` | demo 站（root `demo/`）+ vitest 配置（jsdom、`globals: true` 供 @testing-library 自动 cleanup、测试根指回仓库根） |
| `tsconfig.json` / `tsconfig.build.json` | 前者含 demo/tests 供 `--noEmit` 门禁；后者仅 src、`emitDeclarationOnly`、`rootDir "src"`、`outDir dist/types` |
| `src/css.d.ts` | 一行 `declare module "*.css";`：消除 tsc 产型阶段对 index.ts 顶部 css 副作用导入的 TS2882 |
| `scripts/postbuild.mjs` | 构建后四职责（见下） |
| `src/index.ts` | 唯一公共出口：顶部 css 副作用导入用于构建图谱验证 + 包内消费；对外样式入口是 `./tokens.css` 显式导入 |
| `src/theme/` | `tokens.css`（深色 `:root` 默认）、`tokens.ts`（TS 变量名镜像）、`ThemeProvider.tsx`（class 载体 + 深色默认） |
| `src/commands/` | `keybinding.ts`（纯函数）+ `useHotkeys.ts` |
| `src/dock/` | `DockHost.tsx` + `DockPanel.tsx`（无拖拽） |
| `src/ui/` | 通用控件目录占位，首版为空 |
| `demo/` `tests/` `smoke/` | 自写 demo 站；vitest 四组用例；file: 自包含消费验收 |

**postbuild 四职责**：① 复制 `src/theme/tokens.css` → `dist/tokens.css`（断言非空）；② glob 清理 `dist/es/*.css` 孤儿（产物名依赖包名，不写死）；③ React 外置双向断言（bundle 含 `from"react"` 外部引用、不含 `Symbol.for("react.` 内部标记）；④ 任一失败非零退出。

**门禁**：`npm run check` = `tsc --noEmit && eslint . && vitest run && npm run build`；`npm run build` = `vite build --config vite.lib.config.ts && tsc -p tsconfig.build.json && node scripts/postbuild.mjs`；`npm run smoke` 独立于 check 链，但**自身前置 `npm run build`**——exports 全部指向 `dist/`，缺 dist 时其第①步 import 即失败（「独立」仅指不挂在 check 链里，不是无前置拿来就跑）。

## 三、四轮评审修订记录

1. **第 1 轮**：demo 放弃 Ladle / Storybook 类方案，用自写极简页。实测依据：`@ladle/react@5.1.1` 把 vite 锁为直接依赖 ^6.0.5（非 peer）、2025-11-04 起停更、直接依赖 40+。组件量 ≥10 或需要交互回归时按当期生态重新评估。
2. **第 2 轮**：d.ts 交付链路定夺——`npm run build` 三段链（vite lib → tsc 产型 → postbuild），smoke 断言 `dist/types/index.d.ts` 存在且非空；`react@19.3.1` 无 `types` 字段，本包 d.ts 是第一个 TS 消费方类型的唯一来源。
3. **第 3 轮**：样式显式导入单一路径。实测证伪「import 主入口即得样式」（vite 8 lib 剥离 js 产物的 css 引用）；对外统一 `import '@baigong/fang/tokens.css'`；不走 css 回注方案（需引插件且 node 22 加载含 css import 的 js 必炸）。
4. **第 4 轮（B1/B2）**：
   - **B1 external**：vite 8（rolldown/oxc 底座）lib 模式不自动外置 React——缺省 external 时产物 36,529 字节、React 整体打入、四道门禁失明；加 external 后 132 字节、外部引用保留。external 写进 `vite.lib.config.ts`，postbuild 增双向断言防回归。
   - **B2 css shim**：typescript 6.0.3 对 css 副作用导入报 TS2882（exit=2），`src/css.d.ts` 一行 shim 实测消除（exit=0、d.ts 正常产出）。选 shim 而非引 `vite/client`：构建期类型面更纯净。顺带发现产出的 d.ts 保留 css 副作用导入——消费方若关 `skipLibCheck` 且无 css 模块声明会遇同号报错（Vite 脚手架默认 `skipLibCheck: true` 已覆盖，README 消费节有提示）。

## 四、实测留档清单（八条）

以下均经 %TEMP% 探针独立复现（设计期），施工期在 fang 仓库内再次全量验证（见文末「施工期验证记录」）：

1. `eslint-plugin-react-hooks@7.1.1` peer 含 `eslint ^10.0.0`。
2. `@vitejs/plugin-react@6.1.2` 除 `vite ^8.0.0` 外三个 peer 均为 optional。
3. `react@19.3.1` 无 `types` 字段——消费方类型只能来自本包 d.ts。
4. `@testing-library/react@16.3.3` peer 明列 `@types/react`、`@types/react-dom` 与 `@testing-library/dom ^10`。
5. **【vite 大版本升级必须重验】** vite 8.3.4 lib 模式剥离 js 产物的 css 引用（两轮探针交叉复现；独立 `[name].css` 仍产出）。
6. **【vite 大版本升级必须重验】** node 22.22.2 可直接 `import` 无 css 引用的外置型 lib 产物。
7. **【vite 大版本升级必须重验】** vite 8.3.4 lib 模式**不自动外置 react**，需 `rollupOptions.external` 显式声明（rolldown/oxc 底座，不能凭 rollup 时代记忆；探针 36,529 → 132 字节）。施工期补充实测：vite 8 的 `lib.fileName` 函数返回值**不自动补扩展名**，需返回完整 `"index.js"`；且缺省 `fileName` 时产物按包名命名（`@baigong/fang` → `fang.js`），与 exports 指向的 `index.js` 不一致——故显式钉死。
8. typescript 6.0.3 对 css 副作用导入报 TS2882，`declare module "*.css";` shim 消除。

## 五、推迟项（roadmap，不做即不猜）

- 停靠面板的拖拽、浮动、Tab 化、工作区布局保存与切换——全项目最大过早抽象风险点，等第一个真实工具的面板需求沉淀。
- 命令面板 UI、键位用户自定义与持久化——命令集还不存在，先只交付解析器与 useHotkeys。
- 上下文选项栏组件——无真实内容样例，空壳不进 API。
- 通用控件库（滑杆、取色器、树、表格、拖拽式数值输入）——逐个按工具真实需求进，首版一个都不做。
- 菜单栏组件——Tauri 原生菜单与 Web 菜单的取舍需等第一个工具定夺。
- Tauri 窗口/IPC 约定层——无运行中消费方验证。
- 私有 npm registry、git hooks——仍推迟；CI 流水线已于 2026-10-19 部分落地（仅 develop/qa 门禁，见「八、CI 流水线决策」），main 正式发布流水线与 registry 发布一并推迟。
- Storybook / Ladle——当前放弃；组件量 ≥10 或出现交互回归需求时按当期生态重新评估。
- tsc 级的类型消费验证（smoke 里装 typescript 写 .ts import 本包后 `--noEmit`）——smoke 只锁 d.ts 文件交付，类型正确性留给第一个真实 TS 消费者。
- 「样式随主入口自动注入」类体验（css 回注/inject）——实测证伪后明确放弃，不为它引依赖。
- 亮色主题——深色是唯一既定默认，亮色等需求。
- monorepo 工具——与集群约定冲突且单包无需。

## 六、风险与持续验证点

- **vite 大版本升级**：必须重验留档 ⑤⑥⑦ 三条构建行为；vite 8 底座为 rolldown/oxc，不能凭 rollup 时代记忆假设行为。
- **样式显式导入是刻意约定**：消费方漏 `import '@baigong/fang/tokens.css'` 时 UI 无样式，由 README 醒目说明与 demo 示例引导缓解。
- **`file:` 链接形态**：本机 npm 10.9.7 / Windows 实测为 symlink（smoke 第④步持续记录）；若为复制，fang 侧改动需消费方重装或走 alias 联调轨。另注：node ESM 默认 realpath 语义（`--preserve-symlinks` 关闭），symlink 形态下 `import.meta.resolve("@baigong/fang")` 会落到仓库真实路径——smoke 的④因此从自身位置推导安装副本，不依赖 resolve 结果。
- **keybinding 的「正确形状」**依赖真实工具反馈：首版只覆盖字符串→事件匹配的公共子集，macOS 平台差异等真实需求出现再进。
- **六个消费项目全部无代码**：一切「被消费」验证以 smoke 自包含工程为准；semver 纪律靠自律维持，无 CI 强制。

## 八、CI 流水线决策（2026-10-19，追加条目）

> 远程托管就绪（GitLab 私有实例 `baigong/fang`，项目 id 13，GitLab 19.2.1）后，第五节推迟项中的「CI 流水线」部分落地。范围刻意收窄：**只建 develop / qa 门禁，不建 main 流水线**——正式版打包、registry 发布与 main 流水线一并推迟，等 registry 轨定案后整体补齐。

- **触发范围**：`.gitlab-ci.yml` 的 `workflow:rules` 只认三处——push 到 `develop`、push 到 `qa`、目标为 develop/qa 的 MR（在合并 ref 上跑同一套门禁）。push 到 `main` 不产生任何流水线。配置经 GitLab CI lint（dry_run）实测：develop ref 只出 `gate` 作业，`qa-pack` 正确缺席，规则行为符合预期。
- **镜像 `node:22-bookworm-slim`**：glibc 系（esbuild/rolldown 平台二进制按 glibc/musl 分发，slim 体积小且兼容），跟随 node 22 主版本浮动，满足 engines `>=22.12.0`；不选 alpine（musl）以免踩平台二进制坑。前提是 runner 为 docker 执行器。
- **门禁单一作业 `gate`**：`npm ci --prefer-offline` → `npm run check` → `npm run smoke`，与本地全量门禁完全同链，刻意不拆 lint/test/build 多作业——本仓纪律是「check 即门禁」，拆分只增加每作业重复 `npm ci` 的成本，失败定位靠作业日志已足够。
- **smoke 必须与 check 同作业**：`smoke/verify.mjs` 第①步的 `import("@baigong/fang")` 经 realpath 落到仓库根 `dist/es/index.js`，外置的 `react` 从仓库根 `node_modules` 起解析（第六节 file: 链接形态留档的同源事实）——smoke 需要根 node_modules 与 dist 同时在场，拆独立作业要额外搬运两者，不划算。
- **缓存**：顶层 `variables.npm_config_cache` 指到项目内 `.npm/`，key 以 `package-lock.json` 哈希，smoke 的 `--prefix` 安装共享同一缓存。实测留档：GitLab 19 的 `default:` **不支持 `variables` 键**（CI lint 拒绝，`contains unknown keys: variables`），必须放顶层。
- **qa 独有作业 `qa-pack`**：qa 分支推送时 `npm pack` 出 tgz 作为 CI 制品（14 天过期），测试侧 `npm i <tgz>` 即可试用当前版本。刻意不做：不改版本号（tgz 版本号即 package.json 现值）、不发布 registry——发布属 main 流水线职责，整体推迟。`gate` 的 dist 制品 3 天过期且 `when: always`，仅供 qa-pack 取用与失败排查，不作为交付物。
- **runner 现状（2026-10-19 实测）**：实例尚无可用 runner——早前 Auto DevOps 流水线（id 32）全部作业自创建起停在 `created`、`runner: null`（该流水线已手动取消）。本配置落地后作业将以 pending 等待，直到注册 runner（docker 执行器、可拉取 node 镜像）；配置与 runner 就绪解耦，先萟能力，runner 注册后流水线即自动执行。
- **遗留（需网页端处理）**：项目 `auto_devops_enabled` 仍为 true（API 侧可用工具不含该字段，未改动）——main 等无 CI 配置的分支被推送时仍会自动生成 Auto DevOps 卡死流水线，建议在项目 Settings → CI/CD → Auto DevOps 关闭默认流水线。
